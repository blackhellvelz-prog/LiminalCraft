# MODDING_PLAN

## Платформа и инструменты

**Целевая платформа, подтверждено [FILES]:**
- Minecraft 1.20.1, Forge 47.x. Основной мод требует `[47.4.10,48)`.
- Java 17.

**Методика Universal Modder** (https://github.com/rehan-remade/universal-modder, файл `skills/mod-any-game/references/engines/minecraft.md`, проверено 2026-10-12, ветка main). Применимые к проекту пункты:
- Forge MDK, official mappings, JDK 17. Оракулы — `runClient` и `runServer`.
- Самотесты держать за Gradle-флагом (`-Pselftest`). Никогда не запускать две Gradle-сборки одновременно.
- В dev-среде имена Mojang, в собранном JAR — SRG. Поэтому всё нужно проверять **в реальном JAR в реальном экземпляре**.
- Сетевому каналу задавать явную версию протокола.
- Конфиг TOML не перезаписывать «на лету» через `ConfigValue.set()` + `save()`: файл может обрезаться.
- Звуки только mono, иначе нет позиционирования.
- Работать в отдельном профиле лаунчера со своим `gameDir`.

## Архитектура (предлагаемая, до подтверждения аудитом)

1. **Конфигурация основного мода, без кода.** Отключить переносы из Верхнего мира (см. AUDIT_REPORT §4).
2. **Отдельный аддон** `liminalcraft` (Forge 47.x, Java 17), зависимость от `liminalspaces` объявлена как `mandatory=true`. JAR основного мода не меняется. В аддоне:
   - сюжетное состояние (SavedData на сервере, capability или persistent NBT игрока);
   - журнал;
   - триггеры достижений;
   - кубоидные существа;
   - модули генерации через события загрузки чанков, только в разрешённых `dream_overhaul`-сценах с повторяющейся раскладкой;
   - debug-меню (нативный `Screen`, пакеты C2S с проверкой прав).
3. **Datapack/resourcepack внутри аддона.** JSON достижений, lang `ru_ru`/`en_us`, модели, текстуры 16×16/32×32/64×64, звуки.
4. **Mixin/coremod — только при необходимости.** Пример: полное отключение «floor falls», если конфигом нельзя. Перед этим описать точку вмешательства, риск и откат.

## Резервное копирование и откат (выполняет пользователь на своей машине)

1. Закрыть игру.
2. Скопировать целиком `<instance>/saves/<мир>`, `<instance>/config`, `<instance>/mods`, `options.txt` в `<instance>/_backup_YYYYMMDD/`.
3. Создать **отдельный** профиль лаунчера с новым `gameDir` и копией модов, конфигов и **копией** мира.
4. Откат: удалить JAR аддона, вернуть `config` из резервной копии.
   - Измерения основного мода аддон не меняет, так что ID сохранятся.
   - Блоки, вставленные модулями, останутся в уже сгенерированных чанках. Поэтому сначала тестировать только на копии мира.

## Порядок работы

| Этап | Статус |
|---|---|
| 0. Разведка | **Частично.** Лог, моды и мир пользователя отсутствуют. |
| 1. Аудит модов и лога | **Заблокирован**, нужен лог и список `mods/`. |
| 2. Аудит основного мода | **Частично выполнен** на публичной копии JAR (манифест 175 измерений, 10 существ, конфиги, coremod). |
| 3. Дизайн-документы | Ожидает. |
| 4. Прототип, затем debug-меню | Ожидает. |

Прототип ТЗ требует собрать вместе: одно существо или эффект, ограниченный измерением, + модуль + запись журнала + достижение + каркас debug-меню.
